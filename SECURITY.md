# Security policy

This is an early educational prototype, not an approved environment for regulated or identifiable participant data. Do not place API keys, participant interviews, contact lists, medical details or passwords in Issues, Pull Requests, example data, or public repositories.

If you discover a vulnerability, contact the official project maintainers privately via GitHub security advisory when the public repository has enabled private vulnerability reporting. Avoid publishing exploitation steps while a fix is being prepared.

Only maintainers approve changes to official releases. Never bypass review or introduce hidden remote requests, telemetry, or payment prompts. Dependencies are intentionally avoided in v0.1.
